# Enlaces de resumen con código temporal

La app solicita enlaces protegidos al backend y presenta el código de seis dígitos en `components/security/HandoffAccessCode.tsx`. La API y el contador viven en `services/security/`. El servidor genera el código; la app no recibe semillas ni secretos de generación. El código permanece en memoria y se borra al vencer, ante un error o al pasar a segundo plano. Al volver, se consulta de nuevo. Los ceros iniciales se conservan.

La apertura del enlace se realiza en la web `/handoff/:token`: no existe una pantalla pública de resumen equivalente en la app móvil. Por ello, antes de distribuir esta función deben estar desplegados tanto el backend con protección por código y concesión de acceso como la web con el formulario de seis dígitos. Volver a una versión antigua de la web impide abrir los enlaces protegidos nuevos; los enlaces anteriores sin código mantienen su flujo anterior. Un rollback debe coordinar ambas aplicaciones y conservar la compatibilidad del backend con los enlaces ya emitidos.

`EXPO_PUBLIC_WEB_URL` permite configurar el origen de esa web. Por defecto se usa `https://yuyay-frontend.vercel.app`, el despliegue oficial documentado en el repositorio. No se usa `EXPO_PUBLIC_API_URL` para construir enlaces públicos. Para una prueba local se configura el origen del servidor web de prueba; ese host debe ser alcanzable desde el dispositivo que abre el enlace. El mensaje compartido incluye la URL pública, nunca el código temporal. El cuidador comunica el código por separado.

Crear una sesión envía `requireAccessCode: true`. La app sólo presenta y permite compartir el enlace creado si la respuesta confirma `accessCodeRequired: true`. Si un backend anterior ignora el campo, se muestra un error y no se expone ni comparte automáticamente el enlace resultante. Esa sesión sin protección puede quedar registrada en el backend; el cuidador puede revocarla desde la lista. Las sesiones anteriores sin la propiedad, o con valor `false`, se etiquetan como «Sin protección por código».

El contador usa `expiresAt - serverTime` y tiempo monotónico transcurrido, descontando conservadoramente la latencia. Se consulta al mostrar el panel, al recuperar el primer plano y al vencer el periodo. `consumed: true` con `code: null` muestra «Código utilizado» hasta la siguiente renovación. No hay sondeo adicional ni notificaciones push de consumo: el servidor impide reutilizar un código aunque otro panel todavía lo muestre dentro del mismo periodo.

No se añaden dependencias ni módulos nativos. El indicador circular reutiliza `react-native-svg`, que ya forma parte de la app. Se mantienen React Navigation y los temas claro y oscuro existentes. Las pruebas automatizadas cubren el contrato HTTP, el contador, la cancelación, el consumo y las URL. La comprobación visual y del ciclo de vida en un teléfono real sigue pendiente.
